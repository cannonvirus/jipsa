# 낱말 고르기 규칙

보고서, 결과지, Slack 글, 작업자와 서브에이전트가 쓰는 글의 낱말을 고르는 규칙이다. 기술 영어를 낱말 단위로 옮겨 만든 말(씨앗, 장부, 작은 손질, GPU 할당 뜻의 몫)을 막고, 처음 읽는 동료가 바로 알아듣는 말을 쓰게 한다. 보고서 규격(policies/report.md)의 "쉬운 말"을 낱말 단위로 좁힌 것이다.

작업자 지시문(기준 정하기와 Cycle 단계 작업자 포함)과 begin 결과 규격(세션이 서브에이전트 프롬프트에 그대로 붙이는 블록)의 문체 줄, 마감 전 반대 검토 지시문이 이 문서를 가리킨다. 마감 때 검사가 2절 표의 낱말을 보고서 본문과 result.json의 요약, 선택지에서 찾아 결과지에 주의 줄을 남긴다. 검사는 결과를 막지 않는다. 이 문서는 main에 있어야 어느 경로에도 닿는다. 2026-10-29에 만든 뒤 병합되지 않아 2026-10-31 보고서에 "씨앗"이 다시 나왔고, 261031-jipsa-07이 main에 올리면서 고유 명칭 기준(1절 1번)을 더했다.

## 1. 고르는 기준

낱말마다 아래 물음을 차례로 묻고 처음 맞는 줄을 따른다.

1. **코드와 분야의 고유 명칭인가.** 코드 식별자, 설정 이름, 명령 옵션, 모델 이름, 그리고 seed, LoRA, epoch, batch, checkpoint처럼 그 분야에서 영어 그대로 쓰는 이름은 번역하지 않는다. 영어 원문이나 널리 쓰는 외래어 표기(seed 또는 시드)로 쓰고, 쉬운 말로 풀 때도 원어를 괄호로 남긴다. 작업 제목, 완료 기준, 선택지(options) 문장도 같다. 기준 정하기의 1안 문장은 다음 작업의 제목과 기준이 되므로 여기서 번역하면 뒤 작업 전부에 번진다(2026-10-31 사용자 지적).
2. **사람이 승인한 화면과 개념 이름인가.** 규칙에 이름으로 적힌 것(결과지, 등록부, 할 일 줄, 확인 필요, 반대 검토)은 둔다. 단계 이름(이행, Sol 공격)은 화면에는 두고 보고서 본문은 보고서 규격대로 풀어 쓴다.
3. **국내 개발 문서와 업무 보고가 같은 뜻으로 쓰는 한자어나 우리말이 있는가.** 있으면 그것을 쓴다. 임계값, 할당량, 측정값, 수정, 가져오기, 정제, 음성 인식, 항목이 여기에 든다.
4. **그런 말이 없고 영어 음차가 더 널리 읽히는가.** 그러면 음차를 쓴다. 시드, 배치, 클러스터, 샘플, 어댑터, 부트스트랩, 태그, 로드, 마스킹이 여기에 든다. 처음 나올 때 독자가 모를 만한 말이면 원어를 괄호로 붙인다.
5. **일반 우리말로 이미 자연스럽고 뜻이 하나인가.** 그러면 둔다. 표본, 대조군, 기준선, 판정, 대기열, 상한이 여기에 든다.
6. 어느 줄에도 들지 않으면 새 말을 만들지 않고 풀어 쓴다("GPU를 쓰는 작업마다 잡아 둔 메모리").

판단 물음은 하나다. 이 낱말을 처음 보는 동료가 영어 원어를 떠올리지 않고 뜻을 바로 아는가. 아니면 3~6번으로 바꾼다. 1번의 고유 명칭은 원어를 떠올리게 하는 것이 맞으므로 번역하지 않는다.

## 2. 바꿀 낱말

## 3. 문맥에 따라 고른다

뜻이 갈려서 검사에서 빼고 반대 검토가 본다.

| 지금 낱말 | 기준 |
| --- | --- |
| 시험 | 동작 검증은 테스트, 성능 비교는 실험이다. |
| 묶음 | 처리 단위는 배치, 군집 분석은 클러스터, 화면 무리는 묶음 그대로다. |
| 몫 | GPU나 RAM 할당 뜻이면 할당량이다. 일반 뜻(차지하는 부분, 누가 할 일)이면 그대로 둔다. |
| 실측값, 실측치 | 굳은 말이라 둔다. |
| 받은편지함 | 메일은 둔다. 세션 메시지 통은 수신함이다. |
| 갈래 | 분류, 유형이다. |
| 잣대 | 기준이다. |
| 결(소리 결) | 음색이다. |

## 4. 둔다

| 낱말 | 둘 이유 |
| --- | --- |
| 결과지, 등록부 | 사람만 고치는 공통 규칙과 보고서 규격에 이름으로 쓰인다. |
| 표본, 대조군, 기준선 | 통계와 실험 보고에서 굳은 말이다. |
| 판정 | 일반 업무 보고에서 쓰는 말이다. |
| 이행, 공격 | 내부 단계 이름이다. 보고서 본문은 풀어 쓴다. |
| 뼈대 | 개발 글에서 "뼈대 코드"로 쓰는 말이다. |

## 5. 마감 검사

- 언제: 모든 실행의 마감 공통 경로(세션 finish, 스케줄러 작업자 마감, Auto 마감)에서 결과지를 쓰기 전에 한 번 돈다.
- 무엇을: 마지막 시도의 보고서 본문과 result.json의 label, summary, reason, options에서 2절 표의 낱말을 센다. 선택지를 세는 것은 기준 정하기의 1안 문장이 다음 작업의 제목과 기준으로 그대로 가기 때문이다(261031-jipsa-07).
- 세지 않는 곳: 요약 상자를 뺀 코드 블록, 인라인 코드, 경로와 주소, 링크 대상, 큰따옴표와 낫표 안의 인용, `>`로 시작하는 인용 줄, "열어 볼 파일" 줄이다. 낱말 자체를 다루는 보고서는 낱말을 따옴표로 묶어 쓰면 잡히지 않는다.
- 남기는 것: 찾으면 결과지 보고서 아래에 주의 줄 하나("주의: 바꿀 낱말 3곳(씨앗 2, 문턱 1)")를 붙이고 마감 출력에도 같은 줄을 찍는다. 상태, 재시도, Slack 글은 바꾸지 않는다.

## 6. 아직 정하지 않은 것

대시보드와 명령 출력의 화면 문구("GPU 장부: 몫 합, 남은 자리")를 2절 표대로 바꿀지와 결과지 "서랍"을 그대로 둘지는 사람이 정한다. 정하기 전까지 이 문서는 화면 문구를 다루지 않는다.
