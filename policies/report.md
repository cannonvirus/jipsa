# 보고서 규격

작업 하나의 결과는 보고서 한 편이다. 결과는 `runs/<실행ID>/attempt-N/report.md`에 남고, 그림은 같은 폴더의 `figures/`에 둔다. 작업자는 그 파일에 직접 쓰고, 세션의 서브에이전트는 본문을 마지막 답으로 돌려주며 세션이 그 파일로 옮긴다. 대시보드의 보고서 서랍과 `jipsa result`는 이 파일만 보여 준다. 실행ID, 시간, 토큰 같은 메타 정보는 화면이 따로 보여 주므로 보고서에 적지 않는다.

목표는 하나다. 이 작업을 모르는 사람이 1분 안에 무엇을 했고, 결과가 좋은지 나쁜지, 자기가 할 일이 있는지 안다(2026-10-24 사용자 지시로 개정).

## 간편화 규칙

결과지는 하루에 50장 넘게 읽힌다. 짧을수록 좋다(2026-10-26 사용자 선택). 아래 열 규칙을 모든 보고서에 적용한다. 결과지는 굵은 글씨를 배경 없는 금색 글자로 보여 주고, 마침표로 끝나는 굵은 머리말로 시작하는 문단은 왼쪽 금색 막대 소제목 줄로 보여 주므로, 굵게 쓴 곳만 훑어도 결과와 판정이 읽혀야 한다(2026-10-26 사용자 지시).

1. 요약은 결과를 맨 앞에 둔다.
2. 할 일은 사람이 정할 것만 적는다. 다음에 자동으로 돌 일은 쓰지 않는다.
3. 본문 근거는 3줄 이하다. 더 긴 근거는 쓰지 않는다.
4. 표는 판단에 쓰는 것 하나만 둔다.
5. 고를 안은 한 줄씩 적는다.
6. 반대 검토(Sol 공격과 답)는 본문에 쓰지 않는다. 결과지가 "반대 검토 3건: 모두 반영" 한 줄로 줄여 붙이고 원문은 공격 기록에 남는다.
7. 파일 경로와 커밋 번호는 본문에 쓰지 않는다. "열어 볼 파일" 줄만 마지막에 두면 결과지가 접어 둔다.
8. 그림은 하나만 둔다.
9. 굵은 글씨는 핵심 수치와 판정에만 쓴다. 본문 전체에서 4곳 이하이고 한 곳은 20자 이내다. 문장이나 문단 전체를 굵게 하지 않고, 요약 상자의 줄 이름(한 일, 결과, 사람이 할 일)은 이 수에 넣지 않는다. 수치와 판정이 아닌 말은 굵게 하지 않는다.
10. 요약 상자의 줄은 공백 제외로 한 일 50자, 결과 70자, 사람이 할 일 50자 이하다. 도입 문단은 2문장 이하이고, 절은 결과 절과 마지막 절 사이에 많아야 하나만 둔다.

## 맨 위 세 줄

- 제목 바로 아래, 도입 문단보다 앞에 요약 상자를 두고 세 줄을 이 순서로 쓴다.
  - **한 일**: 무엇을 바꾸거나 만들었는지 한 문장.
  - **결과**: 좋아졌는지, 나빠졌는지, 그대로인지를 먼저 말하고 기준과 견준 핵심 수치 하나를 붙인다. "체크 8개 중 6개 통과, 지난번 4개보다 2개 늘었다"처럼 쓴다.
  - **사람이 할 일**: 정할 것이 있으면 무엇을 정하는지와 추천을 한 줄로 쓴다. 없으면 "없다."라고 쓴다.
- 세 줄은 한 줄이 한 문장이고 위 열 번째 규칙의 글자 수를 넘지 않는다. 본문을 읽지 않아도 뜻이 서야 한다. 이 세 줄에는 아래 "쉬운 말" 절의 내부 이름을 쓰지 않는다.
- 결과 줄과 result.json의 summary는 같은 사실을 말한다.

## 쉬운 말

- 독자는 일을 시킨 사람이고 작업의 진행 과정을 따라오지 않았다. 코드를 어떻게 바꿨는지, 함수 이름이 무엇인지는 읽지 않는다. 무엇이 생겼고 어떻게 보이는지, 무엇을 정해야 하는지를 읽는다.
- 내부 이름은 쓰지 않는 것이 먼저이고, 꼭 써야 하면 처음 나올 때 한 문장으로 푼다. 내부 이름은 체크 번호(c1~c8), 단계 이름(이행, 분석과 피드백, 목표 정하기), 실행 경로 이름(실행기, Main 경로), 설정 이름(제어 클로닝, 연속 클로닝), 측정 용어(seed, 대조군, 기준선) 같은 것이다. 풀 때도 코드 식별자, 설정 이름, 모델 이름, seed나 LoRA나 epoch처럼 분야에서 영어 그대로 쓰는 고유 명칭은 번역하지 않고 원어를 그대로 쓰거나 괄호로 남긴다(낱말 고르기 규칙 1절, 2026-10-31 사용자 지적). 풀 것이 셋 이상이면 도입 문단 뒤에 `용어` 상자를 두고 한 줄에 하나씩 '-다'로 끝나는 문장으로 푼다. 한 보고서에 내부 이름은 다섯 개까지다.
- 숫자는 혼자 두지 않는다. 기준이 있으면 기준과 판정(통과, 미달)을 같이 쓰고, 그 숫자가 쓰는 사람에게 무슨 뜻인지 한 마디를 붙인다. "지연 2.7초(기준 5초 이하, 통과). 말을 걸면 3초 안에 대답한다"처럼 쓴다. 기준이 없는 숫자는 무엇과 견준 값인지를 쓴다.
- 과정은 결과를 믿는 데 필요한 만큼만 쓴다. 어떻게 확인했는지는 한두 문장이고, 판단한 예외는 사람이 정할 것과 이어질 때만 쓴다. 결과가 앞이고 과정은 뒤다.
- 한국어 '-다' 평서체로 쓴다. 비유, 의인화, 가운데점, 번역 투를 쓰지 않는다. 문단은 요지 문장으로 시작하고 3문장 안팎이다.
- 분량은 공백 제외 800자를 목표로 하고 상한은 A4 두 장(2,400자)이다. 넘치면 결과와 정할 것을 남기고 과정을 줄인다. 요약 상자만 읽어도 뜻이 서므로 본문은 요약이 말하지 않은 근거와 정할 것의 이유만 쓴다.
- 코드 블록, 함수 이름, 변수와 필드 이름, 파일 이름과 경로, 인라인 코드를 본문과 표에 쓰지 않는다. 대상은 "감사 문서", "기보 폴더"처럼 우리말로 부른다. 어떤 말로 부를지는 낱말 고르기 규칙(policies/wording.md)을 따르고 영어를 낱말 단위로 옮긴 새 말을 만들지 않는다. 독자가 열어 볼 파일은 마지막 절 끝의 "열어 볼 파일" 한 줄에만 경로로 모은다. 명령은 독자가 직접 칠 것일 때만 그 줄에 인라인 코드로 쓴다.

## 표

- 표는 한 보고서에 하나만 둔다. 사람이 판단에 쓰는 것만 둔다. 측정값 전부나 시험한 경우 전부를 늘어놓는 표는 두지 않고, 그런 값은 열어 볼 파일로 넘긴다.
- 수치 표에는 기준과 판정(통과, 미달)을 같이 둔다. 판정이 모두 같으면 표 대신 한 문장으로 쓴다.
- 표는 4열 이하, 8행 이하이고 칸 하나는 한 문장 안이다. 칸 안에 근거 경로, 영문 식별자, 괄호 속 세부를 넣지 않는다. 근거가 필요하면 표 아래 한 문장으로 쓴다.
- 칸이 길어지면 표가 아니라 문단이나 그림으로 바꾼다.

## 그림

- 그림 하나는 질문 하나에 답한다. 그리기 전에 그 질문을 한 문장으로 적어 보고, 적지 못하면 그리지 않는다. 그림 바로 위 문장이 "이 그림이 보여 주는 것"이고 그 질문의 답이다. 예: "Cycle 하나를 끝까지 돌 때 Slack 알림이 8번에서 2번으로 준다."
- 비교 대상, 축, 단위를 그림 안에 적는다. 전후 비교는 전과 후를 같은 축에 둔다. 강조색은 바뀐 쪽 하나에만 쓴다.
- 그리지 않는다: 값이 2~3개뿐인 그림, 값이 모두 0이나 1인 막대(그것은 목록이다), 표를 색칸으로 옮긴 그림, 본문 표와 같은 내용을 되풀이하는 그림, 시험한 경우를 한 줄씩 늘어놓은 그림.
- 작업 종류별 기본 그림은 아래와 같다. 맞는 것이 없으면 질문 하나를 정해 그린다.

| 작업 종류 | 기본 그림 |
| --- | --- |
| 화면을 바꾼 작업 | 바뀐 부분의 전후 화면 한 장 |
| 수치를 개선한 작업 | 핵심 지표 하나의 전후와 기준선 한 장 |
| 동작이나 흐름을 바꾼 작업 | 한 번 돌 때의 흐름 도식, 전후 두 줄 |
| 조사, 감사, 문서 작업 | 결론을 받치는 수치 그래프나 항목 상태 도식 |
{caption="작업 종류별 기본 그림"}

- 그림은 하나만 둔다. 전후 비교는 한 장 안에 나란히 담는다. 의미 있는 그래프가 없으면 결과물 화면이나 상태 도식 한 장으로 대신한다. 그것도 뜻이 없는 작업(규칙 문구 한 줄 수정 등)은 그림 없이 쓰고 도입 문단에 그림이 없는 이유를 한 문장으로 적는다. 억지 그래프는 그림이 없는 것보다 나쁘다.
- 그림은 수치 그래프, 상태나 구조 도식, 결과물 화면(발행 미리보기, 앱이나 대시보드 화면, 생성한 그림), 입력이나 출력의 사진 가운데 하나다. 마크다운 문서, 표, 코드, 로그, 터미널 출력의 캡처는 그림으로 치지 않는다. 그림 안의 글자는 짧은 우리말 명사구이고 경로, 식별자, 내부 이름을 넣지 않는다.
- 웹 화면을 찍을 때는 바뀐 부분만 잘라 찍는다. 글 전체를 세로로 길게 찍지 않는다.
- `figures/` 아래 PNG로 둔다. 파일 이름은 그림이 답하는 내용을 짧게 쓴 우리말이다(예: 알림-전후.png, 지연-전후.png). 폭은 1,280px이다.
- 웹 화면은 jipsa 저장소의 `tools/md_shot.py --url`로 찍는다. 실제 경로가 든 명령은 작업 지시에 온다.

```
uv run --project <jipsa 폴더> --with playwright python <jipsa 폴더>/tools/md_shot.py --url http://localhost:8000/<글>/ --height 1400 --out figures/screen-미리보기.png
```

- 수치 그래프와 도식은 matplotlib 등으로 그린다. 배경과 색은 대시보드와 같은 어두운 바탕과 금색 강조를 쓴다.
- 그림 제목(대체 문구)은 "~ 화면", "~ 구조", "~ 비교" 같은 명사구다. 번호는 붙이지 않는다.
- 찍은 그림은 반드시 열어 보고 글자 겹침과 잘림을 확인한다. 화면에 비밀값, 메일 주소, 서버 주소가 없어야 한다. 밖에 두지 않기로 한 자료는 찍지 않는다.

## 구성

```
# <작업 이름>

~~~요약
**한 일**: 한 문장.
**결과**: 좋아졌다, 나빠졌다, 그대로다 가운데 하나와 기준을 붙인 **핵심 수치**.
**사람이 할 일**: 정할 것과 추천 한 줄. 없으면 "없다."
~~~

도입 문단 하나(2~3문장). 왜 이 일을 했는지와 어떻게 확인했는지.

~~~용어
내부 이름이 셋 이상일 때만 둔다. 한 줄에 하나, '-다'로 끝나는 문장.
~~~

## 1. <결과를 말하는 명사구>
첫 절이 결과다. 그림 위 한 문장, 그림, 판단에 쓰는 표 순서다.

이 그림이 보여 주는 것 한 문장.

![그림 제목](figures/알림-전후.png)

## 2. <바뀐 동작이나 원인>
필요할 때만 둔다. 사람이 알아야 할 바뀐 동작, 원인, 판단한 예외.

## 남은 일과 정할 것
마지막 절이다. 사람이 정할 것은 번호 목록으로, 추천을 맨 앞에 둔다. 항목마다 고르면 무엇이 달라지는지 한 문장을 붙인다. 없으면 "없다"고 한 문장으로 쓴다.

열어 볼 파일: <저장소>/docs/결과.md
```

위 틀의 물결표 세 개는 실제 보고서에서 백틱 세 개(```요약, ```용어)로 쓴다. 절은 결과 절, 필요하면 바뀐 것 절, 마지막 절로 2~4개다. 소제목은 명사구다(15~25자). 문장형과 질문형은 쓰지 않는다. 같은 절 이름을 모든 보고서에 억지로 맞추지 않는다. 다만 첫 절은 결과이고 마지막 절은 "남은 일과 정할 것"이다.

## 같이 쓰는 result.json

- `status`는 완료, 실패, 확인 필요 중 하나다. `label`은 결과를 한글 두세 단어로 적는다(예: 문서 초안, 수집기 제작). `summary`는 80자 안의 한 문장이고 경로, 파일 이름, 커밋 해시, 내부 이름을 넣지 않는다. Slack 알림의 결과 줄로 그대로 나가고, 넘치면 잘린다.
- `label`과 `summary`는 요약 상자의 결과 줄과 같은 사실을 말한다.
- `changed_files`, `evidence`, `commit`, `reason`, `rule`, `options`, `added_packages`는 그대로다.

## 점검표

- 요약 상자가 제목 바로 아래에 있고 한 일, 결과, 사람이 할 일 세 줄이다
- 결과 줄이 좋아졌는지, 나빠졌는지, 그대로인지를 기준과 함께 말한다
- 세 줄에 내부 이름이 없고, 본문의 내부 이름은 처음 나올 때 풀었으며 다섯 개 이하다
- 숫자마다 기준과 판정이나 비교 대상이 붙어 있다
- 그림마다 답하는 질문이 있고 그림 위 한 문장이 그 답이다
- 값이 0과 1뿐인 막대, 표를 옮긴 그림, 문서, 표, 코드, 로그를 찍은 그림이 없다
- 그림을 모두 열어 봤다. 그림이 없으면 도입 문단에 이유가 있다
- 표가 판단에 쓰는 것만이고 4열 8행 이하이며 칸이 한 문장 안이다
- 공백 제외 800자 목표, 2,400자 이하이고 요약 상자 줄이 한 일 50자, 결과 70자, 사람이 할 일 50자 이하다
- 굵은 글씨가 핵심 수치와 판정에만 있고 본문에 4곳 이하다
- 코드 블록, 함수 이름, 파일 이름과 경로, 인라인 코드가 본문과 표에 없다(마지막 "열어 볼 파일" 줄은 예외)
- result.json의 summary가 80자 안의 한 문장이고 경로, 파일 이름, 커밋 해시가 없다
- 마지막 절이 "남은 일과 정할 것"이다
- 비유, 가운데점, 번역 투가 없다
- 영어를 낱말 단위로 옮긴 말(씨앗, 장부 등)이 없고 seed, LoRA, epoch 같은 고유 명칭은 원어 그대로다
- 본문 근거가 3줄 이하, 표가 하나, 그림이 하나이고 반대 검토 표와 커밋 번호가 본문에 없다
