# todo

할 일 파일(상태 폴더의 todo.md)을 보고, 넣고, 지우고, 한 줄을 바로 시킨다. 같은 파일의 메모 절에 자유 글 메모를 넣고 지우며, 메모를 할 일로 올린다. 넣은 할 일과 메모는 그대로는 돌지 않는다. 한 줄을 지금 돌리려면 `run`으로 시키고, Cycle 줄은 시킬 때 시작과 마감을 정한다. Auto 모드는 없어졌다(261029-jipsa-17). 할 일 파일에 없는 일을 세션에서 바로 맡기는 것은 `/jipsa` 절차다.

## 절차

1. 사용자가 친 인자를 바꾸지 않고 그대로 넘긴다. 세로 막대가 셸 파이프로 읽히지 않게 인자 전체를 작은따옴표 하나로 감싼다.
   - `/todo` → `uv run jipsa todo`
   - `/todo rm <번호|문장 일부>` → `uv run jipsa todo rm '<번호|문장 일부>'`
   - `/todo add <나머지>`나 `/todo <프로젝트> <나머지>` → `uv run jipsa todo add '<프로젝트> <나머지>'`
   - `/todo memo <글>` → `uv run jipsa todo memo '<글>'`. 인자 없는 `/todo memo`는 `uv run jipsa todo memo`로 메모만 본다
   - `/todo memo-rm <번호|글 일부>` → `uv run jipsa todo memo-rm '<번호|글 일부>'`
   - `/todo up <메모 번호|글 일부> <프로젝트> [| <기준> ..]` → `uv run jipsa todo up '<메모 번호|글 일부> <프로젝트> | <기준>'`
   - `/todo cycle <번호|문장 일부> [<지표>] [<목표값>] [이상|이하] [상한 N] [도달하면 끝]` → `uv run jipsa todo cycle '<번호|문장 일부> [<지표>] [<목표값>] [이상|이하] [상한 N] [도달하면 끝]'`. 사용자가 쓴 인자를 그대로 넘기고, 지표와 목표값과 이상이나 이하와 상한과 도달하면 끝은 사용자가 적었을 때만 들어간다. `/todo cycle 3`처럼 번호만 주면 목표 미정 Cycle이다. 비우기는 `/todo cycle <번호> off` → `uv run jipsa todo cycle '<번호> off'`
   - `/todo run <번호|문장 일부> [시작 HH:MM] [마감 HH:MM|+4h]` → `uv run jipsa todo run '<번호|문장 일부> [시작 HH:MM] [마감 HH:MM|+4h]'`. 끝 낱말이 시각이나 길이면 마감으로 읽고, 적지 않으면 시킨 뒤 8시간이다. 시작은 Cycle 줄만 받고 적지 않으면 지금이다
   - `/todo stop <번호|문장 일부>` → `uv run jipsa todo stop '<번호|문장 일부>'`. 시킨 줄을 멈춘다. 돌던 단계는 끝까지 두고, Cycle은 마감 결과지를 쓴 뒤 할 일로 돌아온다. 시작 예정 줄은 예약을 지운다
   - `/todo until <번호|문장 일부> <HH:MM|+2h>` → `uv run jipsa todo until '<번호|문장 일부> <HH:MM|+2h>'`. 시킨 줄의 마감을 고친다
   - `/todo feedback <번호|문장 일부> | <글>` → `uv run jipsa todo feedback '<번호|문장 일부> | <글>'`. cycle 칸이 있는 줄의 도는 Cycle에 사람 피드백을 넣는다. 글은 원문 그대로 다음 분석과 다음 명령 단계의 지시문에 한 번씩 들어가고 판정 기준(지표, 목표값)은 바꾸지 않는다. 스케줄러가 꺼져 있어도 상태 폴더 파일에만 쓴다. 대시보드는 cycle 줄의 피드백 단추가 프롬프트 창 하나로 같은 명령을 돌린다(261026-jipsa-19).
   - 인자 안의 작은따옴표는 셸에 맞게 바꾼다. PowerShell은 `''`처럼 두 번 겹치고, bash는 `'\''`로 쓴다.
2. jipsa 폴더에서 돌리고 출력 그대로를 사용자에게 보인다. 덧붙이는 설명은 없다.
3. 거절되면 출력의 이유만 보이고 다시 돌리지 않는다. 고쳐 넣는 것은 사용자가 한다.

## 줄 양식

`프로젝트 | 할 일 문장 | 기준(선택) | cycle 지표 목표값 이상 상한 N 도달하면 끝(선택) | 한도 VRAM 6GB, RAM 12GB, CPU 4(선택)`

목표 미정 cycle 칸은 `cycle 미정`이고, 하나만 비우면 `cycle 지표 미정 50 이상`, `cycle 첫 글자 지연 목표 미정`처럼 빈 쪽에 미정을 적는다.

- 기준, cycle, 한도 칸은 선택이고 칸 이름으로 가른다. 이름 없는 칸은 기준이다.
- 상한은 나아지지 않은 Cycle을 몇 번 연속까지 볼지이고, 지표와 목표값을 모두 적은 줄에서 상한을 적지 않으면 상한 없이 마감까지 돈다. 지표나 목표값을 비운 목표 미정 줄에서 상한도 비우면 Cycle 1 분석이 상한을 정한다. "도달하면 끝"을 적으면 목표에 닿은 Cycle에서 끝나고, 적지 않으면 닿아도 마감까지 다음 Cycle을 잇는다. 둘 다 cycle 칸이 있어야 쓴다. 기준 칸은 비워도 기준 정하기가 후보 1안을 정해 바로 돈다.
- 등록부에 없는 프로젝트, 빈 문장, 같은 줄, 여러 줄에 걸리는 문장 일부는 명령이 거절한다.

예: `/todo game_ai 2인 점수 올리기 | cycle 고정 시드 40판 평균 점수 50 이상 상한 8`

## 메모

- 메모는 할 일 파일의 `## 메모` 절에 자유 글 한 줄로 든다. 프로젝트와 기준 규칙이 없고 큐가 읽지 않는다.
- 번호는 메모끼리 따로 매기고 목록에 m1, m2로 보인다. 고를 때는 `m1`이나 `1`, 글 일부를 쓴다. `/todo`는 할 일 절 다음에 메모 절을 보인다.
- `memo` 뒤의 글은 첫 낱말이 무엇이든 그대로 넣는다. 지우기는 따로 된 이름 `memo-rm`이다.
- `up`은 메모 한 줄을 할 일 절 끝으로 옮긴다. 메모에서 빠지고 `프로젝트 | 메모 글 | 기준 ..` 줄이 된다. 번호로 고르면 번호 뒤 낱말이, 글 일부로 고르면 마지막 낱말이 등록부 이름일 때 프로젝트다. 세로 막대 뒤 칸은 줄 양식과 같다.
- 프로젝트가 없으면 거절하고 이유를 보인다. 메모 글이 이미 `프로젝트 | 할 일 | 기준` 꼴이면 프로젝트 없이 `up m1`로 그대로 받는다.
- 대시보드 TODO 탭의 메모 칸(넣기 줄, 할 일로, 지우기 단추)도 같은 명령을 돌린다.

예: `/todo memo 요약 한국어로`, `/todo up m1 example_app | 세 피드에서 한국어 요약 줄이 나온다`

## Cycle 목표로 바꾸기

- `cycle`은 고른 줄의 cycle 칸을 채운다. 줄은 제자리에 있고 다른 칸(기준, 한도)은 그대로다. cycle 칸이 있는 줄은 시키면 Cycle 목표로 돈다.
- 인자는 `<번호|문장 일부> [<지표>] [<목표값>] [이상|이하] [상한 N] [도달하면 끝]`이다. 끝에서부터 도달하면 끝, 상한 N, 방향, 목표값(숫자, 단위를 붙여도 된다)을 떼고 남은 낱말이 지표다. 목표값을 적고 방향을 적지 않으면 이상이다.
- 목표 미정 Cycle: 지표나 목표값을 비우면 그 칸을 미정으로 적고 받는다. Cycle 1 이행은 지표 후보와 지금 값을 찾고, Cycle 1 분석이 비운 칸(지표, 목표값, 방향, 그리고 비웠으면 상한)을 정해 그 줄에 채운 뒤 그 값으로 판정한다. 사람이 적은 칸은 덮지 않는다. 지표는 수치 지표나 기계 O/X 체크이고 대리 지표는 쓰지 않는다. 분석이 잴 수단을 찾지 못하면 확인 필요로 끝난다. 정한 값과 근거는 그 분석 결과지의 목표 정하기 절과 끝 결과지에 남는다.
- 상한을 적지 않으면 칸에 적지 않는다. 지표와 목표값을 모두 적은 줄은 상한 없이 돌고, 목표 미정 줄은 Cycle 1 분석이 상한을 정해 채운다. 이미 cycle 칸이 있으면 칸 전체를 덮어쓰므로 옛 상한과 도달하면 끝도 남지 않는다.
- 문장 일부가 여러 낱말이면 세로 막대로 나눈다: `/todo cycle 답변 지연 | 첫 글자 지연 3초 이하`.
- `off`(또는 `해제`, `끄기`)는 cycle 칸을 비운다. 출력에 뗀 칸이 보인다.
- 비울 칸이 없거나 지표를 읽지 못하면 거절하고 이유를 보인다. 시켜서 도는 줄은 거절한다.
- 대시보드 TODO 탭 할 일 줄의 Cycle 단추는 입력 줄 없이 누르면 바로 목표 미정 Cycle을 켜고(`/todo cycle <번호>`와 같다), 켜진 줄에서 다시 누르면 끈다(확인 창이 뜬다). 켜진 줄은 번호 왼쪽에 C가 보이고 지표와 목표값은 C에 마우스를 올리면 툴팁으로 나온다. 값을 넣거나 고치는 것은 이 명령으로 한다.

예: `/todo cycle 3 첫 글자 지연 3초 이하 상한 4`, `/todo cycle 3`(목표 미정), `/todo cycle 3 off`

## 바로 시키기

- `run`은 고른 줄을 시킨다. 일회성 줄은 바로 돌고 시작 시각 예약은 받지 않는다. Cycle 줄은 시작(기본 지금)과 마감(기본 시작 뒤 8시간)을 받는다(261029-jipsa-17).
  - 단발 줄(cycle 칸 없음)은 열린 세션(답 대기 명령이 떠 있는 세션)이 있으면 그 세션의 받은편지함에 Do 요청으로 간다. 답 대기 명령이 안내를 찍고 끝나 세션이 깨고, 세션은 CLI에서 지시받은 것처럼 `jipsa begin --todo`로 열어 서브에이전트에 맡긴다. 열린 세션이 없거나 세션이 2분 안에 받지 않으면 스케줄러 작업자로 넘어간다.
  - cycle 칸이 있는 줄은 세션이 있어도 스케줄러 작업자로 돈다. 단계를 몇 시간씩 차례로 띄우는 일이라 세션 맥락을 오래 차지하지 않게 한다.
  - 작업자로 가는 줄은 2초 안에 시작한다. 시킨 단발 줄은 개수로 막지 않는다. Cycle 새 단계는 합쳐 6개까지다. 사용 창 비율로는 막지 않는다. GPU와 RAM은 장부와 대기열을 거친다. RAM은 시작 5분 동안 잰 최댓값에 여유 1GB를 더해 예약하고, 남은 RAM이 모자라면 대기열에 선다.
- 명령이 거절하는 경우: 같은 줄을 이미 시켰거나 세션에 보냈거나 그 줄이 돌고 있을 때, 등록부에 없는 프로젝트일 때, 세션 전용 프로젝트인데 열린 세션이 없을 때, 기준 정하기가 닫히지 않은 줄일 때. GPU나 같은 원본 폴더 작업자를 기다리는 것은 받아 두고 줄 끝에 이유를 보인다.
- 기준 칸이 있는 줄은 시작하면 할 일 파일에서 빠지고 끝나면 결과지가 남는다. 기준 칸이 없는 줄은 기준 정하기를 먼저 돌려 1안 기준을 그 줄에 적고 같은 요청으로 본 작업을 잇는다. cycle 칸이 있는 줄은 끝 조건이나 마감(적지 않으면 시킨 뒤 8시간)까지 Cycle을 돌고, 마감이면 돌던 단계를 마치고 마감 결과지를 쓴 뒤 할 일 절 맨 아래로 돌아간다. 다시 시키면 멈춘 자리부터 잇는다(판정까지 마친 회차면 다음 회차, 아니면 그 회차의 남은 단계).
- 시킨 줄 끝에는 "시킨 줄. ..." 상태가, 시작한 뒤에는 "도는 중: .. | 시킨 줄" 줄이 `/todo`와 대시보드에 보인다. 스케줄러가 꺼져 있으면 출력에 그 사실이 붙고 켜야 시작한다.
- 대시보드 TODO 탭 할 일 줄의 Do 단추도 같은 명령을 돌린다. 일회성 줄은 바로 시키고, Cycle 줄은 시작과 마감 칸을 펼친다. 시킨 Cycle은 위 띠의 도는 Cycle 줄(멈추기, 마감 고치기, 피드백)이나 시작 예정에 보인다.

예: `/todo run 3`, `/todo run 점수 +4h`, `/todo run 5 시작 22:00 마감 07:00`
