# jipsa-model

모델과 공격 공급자를 질문 5개로 받는다. 인자는 없거나 `show`(`보기`)다. `show`는 `uv run jipsa settings show --skill model` 출력만 보이고 묻지 않는다. 모델 이름은 고유 명칭이라 영어 그대로 받고 번역하지 않는다.

## 같이 지키는 규칙

- 질문은 한 번에 하나다. 질문마다 지금 값(없으면 기본값)을 보이고, 빈 답(엔터)은 그 값을 그대로 둔다. "그만"이라고 답하면 저장하지 않고 끝낸다.
- 잘못 답하면 까닭과 고를 수 있는 값을 보이고 한 번 다시 묻는다. 두 번째도 틀리면 그 칸은 지금 값으로 두고 다음 질문으로 넘어가며 끝 요약에 "건너뜀"으로 적는다. 값 검사는 저장 명령의 검사 동작(`check`, `--check`)에 맡기고 거절 문구를 그대로 까닭으로 보인다.
- 뜻이 분명해도 사람이 적지 않은 값을 스스로 고르지 않는다. "실험"처럼 영어 이름과 다르게 답하면 그렇게 읽어도 되는지 되묻는다.
- 환경 변수가 덮은 칸(`show` 출력에 "환경 변수가 앞선다"가 붙은 칸)은 묻지 않고 "환경 변수가 앞선다. .env를 고쳐야 바뀐다"고 알린다.
- 묻지 않은 칸은 기본값으로 둔다. 끝에 바뀐 칸만 표로 보이고 "이대로 저장할까"를 묻는다. 예라고 답할 때만 저장한다.
- 이 폴더(jipsa)에서 명령을 돌리고 서브에이전트를 띄우지 않는다. 설정 파일과 등록 toml을 직접 고치지 않고 명령으로만 쓴다. 쓰는 명령은 메인 세션 전용이다.
- 명령은 값마다 작은따옴표로 감싼다. 값 안의 작은따옴표는 셸에 맞게 바꾼다. PowerShell은 `''`처럼 두 번 겹치고, bash는 `'\''`로 쓴다.

## 질문

`uv run jipsa settings show --skill model`로 지금 값을 읽어 "모델 설정이다. 지금 값: ..."으로 시작한다.

1. Claude 작업자 모델은? opus, sonnet, haiku 가운데 하나다. 키는 `JIPSA_MODEL_WORKER`다.
2. 판정과 요약 같은 짧은 호출에 쓰는 모델은? 모델 이름 그대로다. 키는 `JIPSA_MODEL_FAST`다.
3. 결과 분석과 반대 검토에 쓰는 Codex 모델은? 키는 `JIPSA_CODEX_MODEL`이다.
4. Codex 작업자 모델은? 비우면 분석자 모델과 같다. 키는 `JIPSA_CODEX_WORKER_MODEL`이다.
5. 마감 전 반대 검토(공격)를 어디에 맡길까? codex, claude, none 가운데 하나이고 기본은 codex다. 키는 `JIPSA_ATTACK_PROVIDER`다. 답하기 전에 세 값을 풀어 준다: codex는 Codex가 하고 Codex 실행 파일이 없으면 공격 없이 돈다(Claude가 대신 공격하지 않는다). claude는 작업자와 같은 계열 모델이 읽기 전용, 도구와 웹 없음으로 새 호출 한 번을 하고 결과지에 "같은 공급자 공격"이라고 적힌다. none은 부르지 않는다. claude는 사람이 직접 고른 경우에만 쓴다. 사람이 고르지 않았으면 codex를 그대로 둔다.

답마다 `uv run jipsa settings check '<키>=<값>'`로 검사한다.

## 저장

바뀐 칸만 전후로 보이고 "이대로 저장할까?"를 묻는다. 예면 바뀐 칸을 쓴다.

```
uv run jipsa settings set '<키>=<값>' '<키>=<값>'
```

"저장했다. 직전 판은 한 장 남겼고 되돌리기는 /jipsa-config undo다"라고 알린다.

## 다시 띄우기

저장한 값은 스케줄러와 대시보드를 다시 띄워야 반영된다. 저장을 끝내면 `uv run jipsa settings show --skill model` 둘째 줄의 실행 중 작업 수를 보이고 "지금 다시 띄울까"를 묻는다. 기본값은 아니오다.

- 예이고 실행 중 작업이 0개면 `uv run jipsa settings restart`를 돌리고 출력을 보인다.
- 실행 중 작업이 있으면 "다시 띄우면 그 작업이 끊긴다"고 먼저 알린다. 그래도 예라고 답할 때만 `uv run jipsa settings restart --force`를 돌린다.
- 아니오면 "다음에 스케줄러가 다시 뜰 때 반영된다"고 알린다. 돌고 있는 작업은 전 값으로 끝난다고 덧붙인다.

## 사용 예

```
/jipsa-model
/jipsa-model show
```
