# jipsa-register

프로젝트 등록 toml 한 장을 질문으로 만들고 고친다. 인자는 프로젝트 이름(영문 소문자, 숫자, 밑줄)과 `edit` 또는 `show`다(`고치기`, `보기`도 받는다).

- 인자가 없으면 `uv run jipsa registry show`로 목록을 보이고 이름을 묻는다.
- `uv run jipsa registry show <이름>`이 종료 코드 1로 "없다"고 하면 새 등록이고, 칸을 보이면 고치기다. `show`를 붙였으면 그 출력만 보이고 묻지 않는다.
- 잘못된 이름(대문자, 공백)은 까닭을 보이고 다시 받는다.

## 같이 지키는 규칙

- 질문은 한 번에 하나다. 질문마다 지금 값(없으면 기본값)을 보이고, 빈 답(엔터)은 그 값을 그대로 둔다. "그만"이라고 답하면 저장하지 않고 끝낸다.
- 잘못 답하면 까닭과 고를 수 있는 값을 보이고 한 번 다시 묻는다. 두 번째도 틀리면 그 칸은 지금 값으로 두고 다음 질문으로 넘어가며 끝 요약에 "건너뜀"으로 적는다. 값 검사는 저장 명령의 검사 동작(`check`, `--check`)에 맡기고 거절 문구를 그대로 까닭으로 보인다.
- 뜻이 분명해도 사람이 적지 않은 값을 스스로 고르지 않는다. "실험"처럼 영어 이름과 다르게 답하면 그렇게 읽어도 되는지 되묻는다.
- 환경 변수가 덮은 칸(`show` 출력에 "환경 변수가 앞선다"가 붙은 칸)은 묻지 않고 "환경 변수가 앞선다. .env를 고쳐야 바뀐다"고 알린다.
- 묻지 않은 칸은 기본값으로 둔다. 끝에 바뀐 칸만 표로 보이고 "이대로 저장할까"를 묻는다. 예라고 답할 때만 저장한다.
- 이 폴더(jipsa)에서 명령을 돌리고 서브에이전트를 띄우지 않는다. 설정 파일과 등록 toml을 직접 고치지 않고 명령으로만 쓴다. 쓰는 명령은 메인 세션 전용이다.
- 명령은 값마다 작은따옴표로 감싼다. 값 안의 작은따옴표는 셸에 맞게 바꾼다. PowerShell은 `''`처럼 두 번 겹치고, bash는 `'\''`로 쓴다.

## 새 등록

"등록에 <이름>이 없다. 새로 등록한다. 질문 5개이고 빈 답은 기본값이다."로 시작해 아래 순서로 묻는다. 종류가 doc이면 6번까지 묻는다.

1. 저장소 폴더 경로는? 기본값은 `registry show` 출력의 경로 기본값이다. 폴더가 없어도 받고 "등록은 폴더를 만들지 않으니 작업 전에 만들어야 한다"고 알린다.
2. 종류는? code, doc, experiment, hardware, game 가운데 하나다. 기본값 code. 정하면 시간 상한 기본값을 알린다(code 90분과 30분, doc 30분과 15분, experiment 3시간과 60분).
3. 사람 없이 할 수 있는 일의 범위를 한 문장으로. 기본값은 "기능 브랜치 커밋까지. 원격 생성과 푸시 없음"이고 doc은 "문서 초안까지. 커밋 없음"이다.
4. 자동 작업이 기능 브랜치에 커밋까지 할까? 예, 아니오. 기본값 예, doc만 아니오.
5. 작업 하나가 잡는 GPU 메모리는 몇 GB인가? 0이면 GPU를 쓰지 않는다. 기본값 0.
6. (doc만) 새 파일을 만들 수 있는 폴더는? 한 줄에 하나씩이다.

답을 모아 먼저 검사한다.

```
uv run jipsa registry new <이름> 'path=<경로>' 'kind=<종류>' 'scope.auto=<범위>' 'scope.commit=<예|아니오>' 'resources.gpu_vram_gb=<수>' --check
```

doc이면 `'scope.allowed_dirs+=<폴더>'`를 폴더마다 더한다. 거절되면 그 칸을 다시 묻는다. 통과하면 답과 기본값을 줄로 보인다. 기본값은 우선순위 50, 작업자 claude, 작업자 모델 비움(전역), 세션 전용 꺼짐, 읽기 금지 .env, 읽기 전용 CLAUDE.md와 AGENTS.md, 외부 읽기와 금지 비움, RAM 0, Ollama 모델 비움, 총 상한과 구간 상한 비움(종류 기본값)이다.

"이대로 저장할까?"를 묻는다. 답은 예, 아니오, 또는 고칠 칸 이름과 값(예: 우선순위 40)이다. 칸과 값을 받으면 `'우선순위=40'`처럼 명령에 더하고 다시 묻는다. 예면 `--check`를 뗀 명령을 돌린다. 출력의 "칸 19개가 읽힌다"와 주의 줄을 그대로 보인다. 새 등록은 스케줄러가 다음 주기에 읽으므로 다시 띄우기를 묻지 않는다.

끝으로 `/jipsa-register <이름> edit`, `/jipsa-register <이름> show`를 알린다. 승인 문구 목록(notes, questions)은 지금처럼 `jipsa registry add`로만 더한다고 덧붙인다.

## 고치기

이미 있는 이름이면 `registry show`의 칸 19개를 표로 보이고 "고칠 칸 이름과 새 값을 적는다. 끝이면 끝"을 되풀이한다.

- 이름 칸은 "파일 이름이라 고치지 않는다"고 거절한다.
- 목록 칸(허용 폴더, 읽기 금지, 읽기 전용, 외부 읽기, 외부 금지, Ollama 모델)은 "더하기 값", "빼기 값"으로 받는다. 명령에는 `'칸+=값'`, `'칸-=값'`으로 넘긴다.
- 값을 비우면 그 키를 지워 기본값으로 돌아간다. 명령에는 `'칸='`으로 넘긴다.

끝이라고 하면 먼저 검사해 바뀐 줄의 전후를 보이고 저장을 묻는다.

```
uv run jipsa registry edit <이름> '<칸>=<값>' '<칸>+=<값>' --check
```

예면 `--check`를 뗀 명령을 돌리고 출력(바뀐 칸 수, 바뀐 줄 수)을 보인다. 주석과 키 순서는 명령이 지킨다. 고친 등록은 스케줄러가 다음 주기에 읽으므로 다시 띄우기를 묻지 않는다.

## 사용 예

```
/jipsa-register ocr_new
/jipsa-register ocr_new edit
/jipsa-register ocr_new show
```
