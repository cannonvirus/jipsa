# jipsa-slack

Slack 보고 설정을 질문 4개로 받는다. 인자는 없거나 `test`(`테스트`) 또는 `show`(`보기`)다.

- `show`는 `uv run jipsa settings show --skill slack` 출력만 보이고 묻지 않는다.
- `test`는 묻지 않고 `uv run jipsa settings slack-test`만 돌려 출력을 보인다.

**Webhook 주소는 비밀값이다.** 세션이 채팅에 다시 적지 않고, 명령 인자로 넘기지 않고, 어디에도 출력하지 않는다. 주소 칸의 값은 설정됨 또는 없음으로만 말한다.

## 같이 지키는 규칙

- 질문은 한 번에 하나다. 질문마다 지금 값(없으면 기본값)을 보이고, 빈 답(엔터)은 그 값을 그대로 둔다. "그만"이라고 답하면 저장하지 않고 끝낸다.
- 잘못 답하면 까닭과 고를 수 있는 값을 보이고 한 번 다시 묻는다. 두 번째도 틀리면 그 칸은 지금 값으로 두고 다음 질문으로 넘어가며 끝 요약에 "건너뜀"으로 적는다. 값 검사는 저장 명령의 검사 동작(`check`, `--check`)에 맡기고 거절 문구를 그대로 까닭으로 보인다.
- 뜻이 분명해도 사람이 적지 않은 값을 스스로 고르지 않는다. "실험"처럼 영어 이름과 다르게 답하면 그렇게 읽어도 되는지 되묻는다.
- 환경 변수가 덮은 칸(`show` 출력에 "환경 변수가 앞선다"가 붙은 칸)은 묻지 않고 "환경 변수가 앞선다. .env를 고쳐야 바뀐다"고 알린다.
- 묻지 않은 칸은 기본값으로 둔다. 끝에 바뀐 칸만 표로 보이고 "이대로 저장할까"를 묻는다. 예라고 답할 때만 저장한다.
- 이 폴더(jipsa)에서 명령을 돌리고 서브에이전트를 띄우지 않는다. 설정 파일과 등록 toml을 직접 고치지 않고 명령으로만 쓴다. 쓰는 명령은 메인 세션 전용이다.
- 명령은 값마다 작은따옴표로 감싼다. 값 안의 작은따옴표는 셸에 맞게 바꾼다. PowerShell은 `''`처럼 두 번 겹치고, bash는 `'\''`로 쓴다.

## 질문

`uv run jipsa settings show --skill slack`으로 지금 값을 읽어 "Slack 보고 설정이다. 지금 주소는 ..., 알림 ..., 아침 요약 ...이다."로 시작한다.

1. Slack Webhook 주소를 붙여 넣는다. 그대로 두려면 엔터다. 받으면 표준 입력으로 넘겨 바로 쓴다. 이 칸은 저장 확인을 기다리지 않는다. 시험 글을 보내려면 먼저 있어야 하기 때문이다.
   - bash는 `printf '%s' '<주소>' | uv run jipsa settings webhook`이다.
   - PowerShell은 `'<주소>' | uv run jipsa settings webhook`이다.
   - 거절되면 거절 문구(주소 꼴)를 보이고 한 번 다시 받는다. 주소를 지우려면 `uv run jipsa settings webhook --clear`다.
2. 시험 글 한 줄을 지금 보낼까? 예, 아니오. 기본값 예. 주소가 없으면 묻지 않는다. 예면 `uv run jipsa settings slack-test`를 돌려 응답 코드를 보이고 "채널에 시험 글이 떴는지 본다"고 말한다.
3. 밤사이 끝난 작업을 모아 보내는 아침 요약 시각은? HH:MM 꼴이다. 지금 값이 기본값이다. "7시 반"처럼 답하면 HH:MM으로 적으라고 다시 묻는다. 검사는 `uv run jipsa settings check 'JIPSA_MORNING_AT=<값>'`이다.
4. Slack 알림을 켤까? 예, 아니오. 기본값은 지금 값이고 대시보드 위쪽 메뉴 스위치와 같은 값이다.

## 저장

바뀐 칸을 보이고(주소는 "없음에서 설정됨"처럼) "이대로 저장할까?"를 묻는다. 예면 주소 말고 바뀐 칸을 쓴다.

```
uv run jipsa settings set 'JIPSA_MORNING_AT=<값>' 'slack.enabled=<예|아니오>'
```

"그만"으로 끝내면 1번에서 쓴 주소는 이미 저장됐다고 알린다. 알림 켜짐과 주소는 바로 반영된다. 아침 요약 시각을 바꿨을 때만 아래 다시 띄우기를 묻는다.

## 다시 띄우기

저장한 값은 스케줄러와 대시보드를 다시 띄워야 반영된다. 저장을 끝내면 `uv run jipsa settings show --skill slack` 둘째 줄의 실행 중 작업 수를 보이고 "지금 다시 띄울까"를 묻는다. 기본값은 아니오다.

- 예이고 실행 중 작업이 0개면 `uv run jipsa settings restart`를 돌리고 출력을 보인다.
- 실행 중 작업이 있으면 "다시 띄우면 그 작업이 끊긴다"고 먼저 알린다. 그래도 예라고 답할 때만 `uv run jipsa settings restart --force`를 돌린다.
- 아니오면 "다음에 스케줄러가 다시 뜰 때 반영된다"고 알린다. 돌고 있는 작업은 전 값으로 끝난다고 덧붙인다.

## 사용 예

```
/jipsa-slack
/jipsa-slack test
/jipsa-slack show
```
