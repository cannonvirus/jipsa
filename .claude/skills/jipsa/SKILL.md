# jipsa 세션 절차

jipsa는 대시보드다. 일을 누가 하든(스케줄러 작업자, 이 세션의 서브에이전트, 이 세션 자신) 기록은 `runs/<실행ID>/`에 같은 모양으로 남고, 끝날 때 확인 필요와 실패면 결과지 요약 세 줄을 담은 Slack 글 하나가 간다. 완료는 바로 보내지 않는다. 이 세션은 유인 모드의 입구다. 자리에서든 Remote Control로 폰에서든 같다. 모든 명령은 jipsa 폴더에서 `uv run jipsa ...`로 돌린다.

## 누가 하는가

분석, 제안, 결론은 반드시 `jipsa begin`으로 열어 서브에이전트가 결과지로 낸다. 채팅에는 실행ID와 시작 또는 마감 사실 한 줄만 쓴다. 메인 세션의 마지막 답이 300자를 넘으면 턴 끝 hook이 "결과지로 낸다"는 경고로 턴 끝을 한 번 막는다(같은 깨어남에서 두 번 막지 않는다, 한도는 JIPSA_CHAT_LIMIT, 261025-jipsa-15).

질문(원인, 분석, 제안, 맞는지 확인)도 작업으로 열어 결과지로 낸다. 채팅에는 실행 번호와 상태 한 줄만 적는다. 작업을 연 턴이라도 "아니다.", "맞습니다.", "원인은", "때문이다" 같은 판정과 원인을 채팅에 덧붙이지 않는다. 사람 입력이 묻는 말이면 입력 hook이 이 안내를 붙이고, 마지막 답이 300자 안이라도 결론 문장 꼴이면 턴 끝 hook이 같은 방식으로 한 번 막는다(끄기는 JIPSA_CHAT_MARKERS=0, 261025-jipsa-31).

이 메인 세션은 작업을 넣고 의견을 주는 자리다. 메인 세션에서는 작업하지 않는다. 세션의 역할은 작업을 넣고(`jipsa begin`과 서브에이전트 띄우기), 결과를 점검해 마감하고, 사용자에게서 다음 태스크와 피드백을 받는 것이다.

사용자가 시키는 태스크는 크기와 관계없이 항상 서브에이전트가 한다. 반드시 `jipsa begin`을 거치고, 메인 세션은 작업하지 않고 비워 둔다(2026-10-22 사용자 승인). 단 하나의 예외는 서브에이전트가 마지막 답으로 돌려준 보고서와 분석 본문을 바꾸지 않고 파일로 옮겨 쓰는 일이다(아래 "서브에이전트로 일 시키기" 3번, 2026-10-22 사용자 승인).

파일을 바꾸는 일과 분석을 직접 수행하는 일은 프로젝트에 속하든 아니든 모두 서브에이전트가 한다. 작아도 같다. 기록 바로잡기(meta, result.json, 큐), 등록부와 스킬 수정, worktree 준비, 보고서 다시 쓰기, 조사, PC 상태 점검이 그 예다. 작은 일이면 짧은 상한과 가벼운 모델로 띄운다. 순서는 아래 "서브에이전트로 일 시키기"다.

프로젝트에 속하지 않는 점검, 조사, 선정도 서브에이전트가 한다. 기록은 등록부 misc(화면 이름 "기타")로 `jipsa begin misc`를 거쳐 남긴다. 그래야 결과지가 생기고 대시보드 결과지 서랍에서 열린다.

메인 세션은 채팅에 결과를 보고하지 않는다. 결과는 사용자가 대시보드 결과지로 본다. 표, 요약, 수치, 결과 한 줄은 쓰지 않는다. 메인 세션은 사용자에게서 다음 태스크와 피드백만 받는다. 확인 필요 선택지도 채팅에 늘어놓지 않고 대시보드 결과지 서랍의 답 넣기에 맡긴다(2026-10-22 사용자 승인).

이 세션이 직접 하는 것은 다음뿐이다.

- jipsa 명령 실행(begin, attack, finish, topic, status, runs, result, answer, web).
- 서브에이전트 띄우기와 결과 읽기.
- 서브에이전트가 마지막 답으로 돌려준 보고서와 분석 본문을 바꾸지 않고 파일로 옮겨 쓰기.
- 대시보드와 미리보기 같은 백그라운드 서버 켜고 끄기.
- 실행ID와 시작 또는 마감 사실 한 줄 알리기. 사용자의 다음 태스크와 피드백 받기.

세션도 공통 규칙의 검색 범위를 따른다. 결과 점검 때 저장소 전체를 훑지 않고, 내용 검색은 `git grep`이나 `rg`로 하며 `head` 파이프로 자르지 않는다.

## 세션 주제 걸기

"jipsa 온"은 대시보드(`uv run jipsa web --no-open`)를 백그라운드로 켜고 상태만 알린다. 대시보드가 스케줄러가 없으면 창 없는 분리된 프로세스로 함께 띄우고, 출력은 상태 폴더의 스케줄러 로그로 간다. 스케줄러를 `jipsa run`으로 따로 켜지 않는다. 켜도 잠금으로 바로 끝난다. 대시보드를 꺼도 스케줄러는 계속 돈다. Windows 시작 프로그램에는 등록하지 않는다(2026-10-22 사용자 승인). misc나 주제로 기록하지 않는다(2026-10-21 사용자 승인). 답 대기 명령 `uv run jipsa wait-answer --session <세션 기록 id> --timeout 0`은 세션이 `jipsa begin`을 처음 돌릴 때나 hook 안내가 오면 메인 세션이 백그라운드로 띄운다. `jipsa begin`과 턴 끝 hook이 이 세션의 Claude Code 프로세스 아래에서 대기 명령을 찾아, 없을 때만 "[jipsa] 답 대기 명령이 없다. 메인 세션이 백그라운드로 띄운다: <명령>"을 찍는다. 세션 기록 id는 그 안내의 명령에 들어 있다. 안내가 없으면 이미 떠 있으므로 다시 띄우지 않는다. 분리 프로세스로 띄운 대기 명령은 끝나도 세션을 깨우지 못하므로 없는 것으로 친다. 대기 명령은 띄운 세션이 사라지면 스스로 끝난다(2026-10-22 사용자 승인, 261025-jipsa-15).

스케줄러만 끄는 일은 `uv run jipsa settings stop`이다. 실행 중 작업이 있으면 거절하고, `--force`를 주면 그 작업을 끊는다. 대시보드 감시는 다시 띄우지 않으며 `uv run jipsa settings start`나 `restart`가 멈춤을 푼다.

기타 일(PC 점검, 조사, 선정처럼 등록부 프로젝트에 속하지 않는 일)도 서브에이전트에게 맡기고 `uv run jipsa begin misc "<항목>" --criteria "<완료 기준>" --executor subagent --model <모델>`으로 기록한다(아래 "서브에이전트로 일 시키기"). 그 실행은 화면 맨 아래 접을 수 있는 "기타" 묶음 안에 항목마다 한 줄로 뜨고, 결과지 서랍에서 열린다. misc는 세션 전용 등록부라 스케줄러가 자동으로 돌리지 않는다.

세션 주제(`uv run jipsa topic "<대상> <확인|분석|조사|수정>" --project <프로젝트|기타>`)는 실행 기록이 없는 짧은 세션 일에만 건다. `jipsa begin`으로 기록하는 일에는 걸지 않는다. 그 일은 실행 기록 줄에 따로 뜨므로 걸면 같은 일이 두 줄에 나온다. 이미 걸린 주제가 나중에 실행 기록으로 들여와졌으면 meta.json의 그 주제 항목에 `run_id`를 적어 잇는다. 화면은 `run_id`가 적힌 주제를 그리지 않는다.

주제를 건 일이 끝나면 세션이 `uv run jipsa topic --done`으로 주제를 닫는다. 닫지 않으면 세션이 끝날 때까지 그 주제가 진행 중으로 늘어난다. 끝난 지 오래 지나 닫을 때는 `--at "HH:MM"`(오늘 그 시각)이나 `--at 2026-10-21T22:06:22`(ISO 시각)로 실제 끝난 시각을 준다. 미래 시각은 받지 않는다. 이미 닫혔으면 아무 일도 하지 않고, 새 주제를 걸면 앞 주제는 그 시각에 저절로 닫힌다.

## 할 일 넣기 (시켜야 돈다)

사용자가 "example_app에 설정 화면 검증 추가 할 일로 넣어 줘"처럼 나중에 돌릴 일을 말하면 `/todo` 절차로 할 일 파일에 넣는다. 이 세션이 서브에이전트로 바로 맡길 일은 아래 "서브에이전트로 일 시키기"다.

1. 프로젝트 이름을 등록부(`projects/*.toml`)의 파일 이름으로 맞춘다. 없으면 어느 프로젝트인지 묻는다.
2. `uv run jipsa todo add '<프로젝트> <할 일 문장> | <기준>'`을 돌린다. 기준이 말에 없으면 기준 칸 없이 넣는다. 기준 없는 줄은 차례가 오면 기준 정하기 작업이 후보를 쓰고, jipsa가 1안을 기준 칸에 적어 사람 답 없이 본 작업을 돌린다. 넣기만 한 줄은 돌지 않는다.
3. 돌리는 길은 둘이다. 한 줄을 지금 돌리려면 사용자가 `/todo run <번호>`(대시보드 할 일 줄의 Do 단추)로 시킨다. 단발 줄은 이 세션에 답 대기 명령이 떠 있으면 이 세션으로 오고(아래 "Do 요청 받기"), 없으면 2초 안에 스케줄러 작업자로 시작한다. cycle 칸이 있는 줄은 늘 작업자로 돈다. Cycle 줄은 `/todo run <번호> 시작 22:00 마감 07:00`처럼 시킬 때 시작과 마감을 정한다. Auto 모드는 없어졌다(261029-jipsa-17). 세션이 대신 시키지 않는다.
   - 도는 Cycle 목표에 사람의 말을 전하려면 `/todo feedback <번호|문장 일부> | <글>`을 쓴다. 원문 그대로 다음 분석과 다음 명령 단계가 한 번씩 읽고 판정 기준은 바뀌지 않는다(대시보드 피드백 단추). 분석 결과의 다음 명령을 직접 고치지 않는다.
4. 넣었다는 사실을 한 줄로 알린다. 결과는 채팅에 보고하지 않고 대시보드 결과지로 본다.

## Do 요청 받기 (대시보드 Do와 /todo run)

사용자가 대시보드 Do나 `/todo run`으로 시킨 단발 할 일 줄은 이 세션이 CLI에서 지시받은 것처럼 서브에이전트로 돌린다(261026-jipsa-24 2안, 261026-jipsa-26). 답 대기 명령이 몇 초마다 열린 세션 표시를 남기고, 그 표시가 있으면 Do가 받은편지함으로 온다. 답 대기 명령은 "[jipsa] Do 요청: <프로젝트> <할 일> (할 일 N번)"과 기준, begin 예시를 찍고 끝나 세션을 깨운다. 일하는 중이면 hook이 턴 끝이나 다음 입력 때 같은 안내를 넘긴다.

1. 안내의 begin 예시대로 `uv run jipsa begin <프로젝트> "<할 일>" --criteria "<기준>" --todo "<할 일 key>" --executor subagent --model <모델> --agent <이름>`을 돌린다. `--todo`는 그 줄을 할 일 파일에서 빼고 실행 기록에 줄 원문을 남긴다. 줄에 기준이 없으면 할 일 문장에서 세션 안에서 직접 확인할 수 있는 완료 기준 한 문장을 정해 넣는다. 그다음은 아래 "서브에이전트로 일 시키기" 2번부터 같다.
2. 세션이 2분 안에 받지 않으면(답 대기 명령이 없거나 막 끝났으면) 스케줄러가 그 줄을 작업자 요청으로 넘긴다. 같은 줄을 두 번 시키면 거절한다.
3. cycle 칸이 있는 줄의 Do는 세션으로 오지 않고 작업자로 돈다. Cycle은 이행, 분석, 판정 단계를 몇 시간씩 차례로 띄우므로 세션 맥락을 오래 차지하지 않게 한다.
4. begin은 Claude와 Codex 사용 창 비율로 거절하지 않고 Codex로 갈 일을 Claude로 넘기지도 않는다. 프로젝트 GPU 요구량(등록부, 지난 실측 최댓값)이 0보다 크면 begin이 이 세션 프로세스 번호로 GPU 장부에 몫을 적고, finish가 돌려준다. 자리가 모자라면 막지 않고 주의 줄을 찍는다.
5. 세션 서브에이전트는 원본 폴더 잠금에 걸리지 않는다. 같은 폴더에서 여럿을 같이 돌릴 수 있다. 원본 폴더 잠금은 스케줄러 작업자끼리만 건다.

## 서브에이전트로 일 시키기 (이 세션이 돌린다)

사용자가 시키는 태스크는 크기와 관계없이 항상 Agent 도구로 서브에이전트를 띄워 맡기되 반드시 jipsa 기록을 거친다. 기록 없이 띄우면 화면과 보고와 Slack 어디에도 남지 않는다.

1. `uv run jipsa begin <프로젝트> "<항목 이름>" --criteria "<완료 기준>" [--est <분>] --executor subagent --model <모델> --agent <name>`을 돌린다. `--agent`는 2에서 정할 서브에이전트 이름이고 멈춤 알림에 같이 찍힌다. 출력에 실행ID와 서브에이전트에게 줄 결과 규격(result.json 경로와 JSON)이 나온다.
   - begin은 큐 줄과 실행 기록만 만든다. 새 메모는 할 일 파일의 메모 절(`jipsa todo memo`)에 넣는다. 같은 프로젝트의 할 일 줄, 메모, 지난 실행에서 나온 일이면 `--parent "<이름 일부>"`로 실행 기록에만 걸 수 있고, 찾지 못하거나 여럿에 걸리면 begin이 시작하지 않는다(261025-jipsa-42).
   - 세션이 작업 종류를 추정해 `--kind 구현|글쓰기|조사|기획|실험`으로 넣고, 사람이 고를 것이 남는 제안형이면 `--pick`을 더한다. 빠지면 제목 낱말로 추정한다.
   - 사용자가 "초안"이라고 하면 대시보드 결과지의 "초안 보기"로 여는 HTML 초안이다. begin에 `--draft`를 붙인다(입력 hook과 답 대기 명령이 30분 안의 "초안" 요청을 세션 기록에 남겨 두면 붙이지 않아도 begin이 저절로 표시한다). begin 출력 맨 아래 초안 줄(실행 폴더 안 HTML 경로와 preview_url 안내)을 서브에이전트 지시에 그대로 넣어 사람이 볼 HTML 초안을 `runs/<실행ID>/attempt-1/draft/index.html`처럼 실행 폴더 안에 만들고 result.json의 preview_url에 그 경로를 슬래시로 적게 한다. 보고서 본문만 돌려주면 결과지로만 보인다. preview_url이 비었거나 그 파일이 없으면 `jipsa attack`과 `jipsa finish`가 막으므로(종료 2) 서브에이전트에게 채우게 한 뒤 다시 마감한다. 초안과 상관없는 일이면 `--no-draft`다.
   - 조사 자료는 각 작업이 직접 모은다. 미리 모아 주는 단계는 없다(261025-jipsa-42, 사용자 결정).
2. Agent 도구로 서브에이전트를 띄운다. `name`을 정해 준다(예: `ocr-fix`). `model` 인자에 begin의 `--model` 값을 그대로 넘긴다. 생략하면 세션 모델을 물려받으므로 대화가 요약된 뒤에도 호출마다 명시한다(사용자 결정, 261102-jipsa-31 1안). 프롬프트에 넣을 것: RULES.md의 규칙, 등록부의 허용 폴더와 금지 경로, 완료 기준, 그리고 begin이 출력한 보고서와 결과 규격 블록 그대로. 그 블록의 낱말 고르기 규칙 줄(`policies/wording.md`, seed나 LoRA 같은 고유 명칭은 번역하지 않는다)도 빼지 않고 넘기며, 세션이 정하는 제목과 완료 기준 문장도 같은 규칙을 따른다(261031-jipsa-07). 보고서는 `policies/report.md` 규격이다. 한국어 평서체, A4 두 장 안, 맨 위 요약 상자 세 줄(한 일, 결과, 사람이 할 일), 내부 이름은 풀거나 쓰지 않음, 그림은 질문 하나에 답하는 것만이고 억지 그래프 금지, 코드 설명 금지. 서브에이전트가 그 파일을 직접 읽게 한다. Claude Code 내장 검사가 서브에이전트의 Write 도구로 이름이 REPORT, SUMMARY, FINDINGS, ANALYSIS로 시작하는 .md 파일 쓰기를 막으므로(대소문자 무관, 설정으로 끌 수 없음), 프롬프트에 보고서(report.md)와 분석 문서(analysis.md)는 파일로 쓰지 말고 `policies/report.md` 규격의 본문 전체를 마지막 답에 마크다운으로 돌려주라고 넣는다. 셸 쓰기나 이름 바꾸기로 우회하지 말라고도 넣는다. 그림 PNG, result.json, progress.md, search.md와 다른 산출물은 서브에이전트가 지금처럼 직접 쓴다. `--executor subagent`로 연 begin의 결과 규격 블록은 보고서를 본문으로 돌려주라고 이미 안내하므로 그대로 넘긴다(2026-10-22 사용자 승인). result.json은 셸 heredoc이나 echo로 쓰지 말고 파이썬 json.dump로 쓴다. 안의 Windows 경로는 슬래시(<드라이브>:/work/...)로 적는다. 쓴 뒤 다시 읽어 status를 확인한다. 프롬프트에 "긴 계산을 백그라운드로 띄웠으면 차례를 끝내지 말고 끝날 때까지 진행 기록(progress.md)을 갱신하며 기다린다"를 넣는다. 무거운 프로세스는 동시에 2개까지, 병렬 수는 2 이하, 띄우기 전 RAM 여유 4GB 확인도 begin 출력의 같은 줄 그대로 넣는다(2026-10-28 사용자 승인, 261028-jipsa-03 1안).
   - 멈춤 알림: 세션 서브에이전트 실행 폴더에 15분 넘게 활동이 없으면 스케줄러가 멈춤으로 보고, 답 대기 명령이 "[jipsa] 멈춤: <실행ID> (<이름>, <항목>) N분 무활동. 서브에이전트에게 메시지를 보내 깨워라"를 찍고 끝난다. 세션은 SendMessage로 그 서브에이전트에게 "띄운 계산의 상태를 확인하고 이어서 진행하라"를 보내고 대기 명령을 다시 띄운다. 같은 실행은 20분마다 다시 알린다. 서브에이전트는 백그라운드 계산이 끝나도 스스로 깨어나지 못하고 메시지를 받아야 깨어난다(261023-jipsa-29).
   - 자동 닫힘: 세션이 begin한 실행이 마감되지 않은 채 실행 폴더에 30분 동안 활동이 없으면 스케줄러가 닫는다. 결과 파일이 온전하면 그 결과로, 없으면 실패로 닫는다. 상한은 보지 않으므로 상한을 넘겨도 활동이 이어지면 닫히지 않는다. 서브에이전트에게 상한은 예상 시간이고 끊는 시각이 아니다. 화면과 마감 출력은 걸린 분만 보이고 상한의 80% 이상이면 "48분/60분", 넘기면 "75분, 상한 60분 넘김"으로 보인다(261029-jipsa-22 1안).
3. 서브에이전트가 끝나면 마감 전에 결과 파일(result.json)이 있는지 세션이 먼저 확인한다. 없으면 마감하지 않고 서브에이전트에게 쓰게 한다. 세션이 result.json을 대신 쓰지 않는다. 보고서와 분석 문서는 예외다. 서브에이전트가 돌려준 본문을 바꾸지 않고 `runs/<실행ID>/attempt-1/report.md`(분석 문서는 `analysis.md`)로 옮겨 쓴다. 이 옮겨 쓰기는 "메인 세션은 작업하지 않는다" 규칙의 명시된 예외다(2026-10-22 사용자 승인). 옮긴 뒤 result.json이 있으면 아래 Sol 공격 순서를 거쳐 `uv run jipsa finish <실행ID> --agent <name>`을 돌린다. 순서는 보고서 옮겨 쓰기, `uv run jipsa attack <실행ID>`, 같은 서브에이전트에게 공격 글 보내기, 고친 보고서 다시 옮겨 쓰기, finish다(261024-jipsa-09 3안, 2026-10-24 사용자 지시).
   - Sol 공격: `jipsa attack`이 Sol(Codex 기본 모델)을 지금 분석자와 같은 격리(읽기 전용, 도구와 웹 없음, 자료는 입력으로만)로 한 번 부른다. 입력은 원래 요청과 완료 기준, 보고서, result.json 요약과 증거와 체크 칸, 바뀐 내용 앞부분, 증거에 적힌 작은 측정 기록이다. 결과는 시도 폴더의 attack.json과 attack.md다. 판정(통과, 보완, 재작업)과 지적 최대 7개(종류, 심각도 상중하, 문제 주장, 문제, 근거 위치, 확인 방법)이고 근거 위치 없는 지적과 형식 밖 응답은 버린다.
   - 공격 없음: `jipsa attack`은 Codex 창 사용량과 무관하게 호출을 시도한다. 호출이 한도 오류나 다른 오류로 실패하거나 형식 밖 응답이면 `jipsa attack`이 "공격 없음(사유)"를 남기고 그대로 마감하라고 찍는다. 막지 않고 Claude가 대신 공격하지 않는다. 지적이 없으면 답 없이 마감한다.
   - 답 받기: 지적이 있으면 `jipsa attack`이 찍은 글(--- 아래)을 SendMessage로 그 일을 한 같은 서브에이전트에게 바꾸지 않고 보낸다. 서브에이전트는 지적마다 반영, 반박, 사람 가운데 하나로 답해 시도 폴더의 attack_reply.json(`{"replies": [{"no": 1, "answer": "반영", "note": "한 문장"}]}`)에 쓰고, 반영은 보고서를 고치며 짧은 재확인은 15분 안에서 한다. 심각도 상을 반박이나 사람으로 답했으면 보고서 정할 것에 올린다. 고친 보고서 본문은 마지막 답으로 돌려주고 세션이 다시 옮겨 쓴다.
   - 공방은 한 번이다. 답을 받은 뒤 `jipsa attack`을 다시 돌려도 Sol을 다시 부르지 않고 앞 공격을 그대로 찍는다. finish가 공격 요약을 결과지 보고서 아래 접힌 공격과 답 표로 붙이고, 대시보드 실행 줄에 "공격 N, 반영 M, 사람 K"를, Slack 글 머리 줄 끝에 "(Sol 지적 N, 반영 M)"를 붙인다. 공격 기록 없이 finish하면 주의 한 줄이 나온다.
   finish는 Claude Code 기록(jsonl)에서 도구 호출, 토큰, 마지막 보고를 들여오고 결과지를 만들고 그날 보고를 다시 만들고 확인 필요와 실패면 Slack 요약 글을 보낸다. finish를 돌린 뒤 그 서브에이전트를 `TaskStop`(서브에이전트 이름)으로 정리한다. 같은 서브에이전트에게 후속 질문이나 보고서 재전송을 받아야 하면 그 일이 끝난 뒤 정리한다(2026-10-22 사용자 승인).
4. 사용자에게는 실행ID와 시작 또는 마감 사실 한 줄만 쓴다("누가 하는가" 절). 결과지 초안(`--draft`)도 링크를 채팅에 적지 않고 결과지 서랍의 초안 보기 단추로 보게 한다. 대시보드는 초안 실행의 서랍 머리와 현황판 최근 결과 줄, 오늘 끝난 일 표에 초안 표식을 붙이고, 주소가 비면 "초안 주소 없음"을 적는다.

jipsa 자신을 고치는 서브에이전트가 시험할 때는 프롬프트에 "운영 상태 폴더를 쓰지 않는다. 임시 상태 폴더를 JIPSA_STATE_DIR로, 실행 기록과 보고 폴더도 JIPSA_RUNS_DIR, JIPSA_REPORTS_DIR로 임시 폴더를 준다"를 넣는다. 할 일 파일은 상태 폴더 안(todo.md)이라 JIPSA_STATE_DIR로 함께 바뀐다. 에이전트 셸에서 운영 상태 폴더로 스케줄러 루프, 모의 실행, 8765가 아닌 포트의 대시보드를 띄우면 jipsa가 막는다. 운영으로 돌릴 것이 맞으면 JIPSA_LIVE=1을 준다(261023-jipsa-08).
시험 스크립트도 분리 플래그(DETACHED_PROCESS)로 python을 띄우지 않는다. 콘솔 없는 가상환경 python이 새 콘솔 창을 연다. 백그라운드로 띄울 때는 scheduler.nowindow의 hidden(BACKGROUND)를 쓴다(261025-jipsa-17).


여러 개를 동시에 띄울 때는 begin을 먼저 모두 돌리고 Agent를 한 번에 띄운 뒤 끝나는 대로 finish한다.

작업(실행 번호)마다 서브에이전트를 하나 새로 쓴다. 다른 작업을 한 서브에이전트에 합치지 않고, 끝난 서브에이전트에 다음 작업을 이어 맡기지 않는다(2026-10-25 사용자 승인).

끝난 서브에이전트 정리는 다음을 따른다(2026-10-22 사용자 승인).

- 작업 중이거나 백그라운드 명령 결과를 기다리는 서브에이전트는 상태가 idle이어도 마감 전이면 정리하지 않는다. 마감 전인지는 `uv run jipsa status`의 실행 중 목록으로 판단한다.
- 사용자가 요청하거나 세션이 여러 작업을 마감한 뒤에는 `ListAgents`로 남은 서브에이전트를 보고, 실행 기록이 마감된 idle 서브에이전트를 한 번에 정리한다.
- 정리했다는 사실은 메인 채팅에 따로 길게 쓰지 않는다. 위 "메인 세션은 채팅에 결과를 보고하지 않는다" 규칙과 같다.

## 상태와 기록 보기

- `uv run jipsa status`: 모드, 큐, 실행 중, 확인 필요, 리스, 자원.
- `uv run jipsa runs [--last N] [--date YYYY-MM-DD] [--project P] [--status S]`: 지난 작업 목록. 시작 역순, 주체와 토큰 포함.
- `uv run jipsa result <실행ID> [--rebuild]`: 보고서(`runs/<실행ID>/attempt-N/report.md`) 전문. 규격은 `policies/report.md`다.
- `uv run jipsa web`: 대시보드 http://127.0.0.1:8765/ . 타임라인, 트리, 상단 확인 필요 단추, 큐, 환경, 기록 표, 결과지 서랍, 오늘 보고. 터미널을 차지하므로 백그라운드로 띄우고 주소를 알린다. 이미 떠 있으면 두 번째 시작은 포트 오류로 바로 끝난다. 화면은 모델을 부르지 않아 토큰을 쓰지 않는다.
- `python monitor.py`(jipsa 폴더에서): 서비스 Monitor. 콘솔 메뉴로, 대시보드와 스케줄러를 하나의 단축키로 함께 켜기, 끄기, 다시 켜기를 하고 서비스마다 로그 단축키가 있으며 메뉴 위에 상태(떠 있음, PID, 포트, 주소)를 보인다. 엔터는 상태를 새로 읽고, 로그 화면은 끝 40줄이며 300줄로 바꿀 수 있다. 가상환경 밖의 파이썬으로 켜도 가상환경 파이썬으로 다시 실행한다. 서비스 목록은 scheduler/services.toml 한 곳이고, 서비스는 창 없는 분리 프로세스라 Monitor 창을 닫아도 돈다. 사용자가 직접 켜는 화면이므로 세션은 띄우지 않고 명령을 알려 준다. Monitor에서 끈 스케줄러는 대시보드 감시가 다시 띄우지 않고 Monitor나 `jipsa run`으로 켜면 풀린다. 실행 중 작업이 있으면 끄기와 다시 켜기는 거절하고, 확인 문구에 y를 답해야 작업을 끊고 한다(261024-jipsa-22, 23, 261103-jipsa-02).
- `uv run jipsa console`: 같은 내용의 터미널 화면. 사용자가 직접 켤 때만 쓴다.
- `uv run jipsa report [YYYY-MM-DD] [--send]`: 그날의 보고 전문. `--send`는 Slack 요약을 보낸다.

## 확인 필요 답하기

작업이 확인 필요로 멈추면 `jipsa status`에 걸린 규칙과 선택지가 보이고, 대시보드 화면에서는 확인 전 완료와 실패와 함께 상단 확인 필요 단추의 수에 더해진다. 상태 값 확인 필요는 2026-10-22 전에 판단 대기라고 불렀다. 옛 기록의 판단 대기는 읽을 때 확인 필요로 맞춰지고, `--status 판단 대기`도 받는다(2026-10-22 사용자 승인, 261022-jipsa-50). 답을 넣을 것은 막대 툴팁과 상태 칸의 물음표로 가른다. 선택지는 채팅에 늘어놓지 않고 대시보드에 맡긴다. 사용자가 상단 확인 필요 단추(또는 타임라인의 주황 막대)를 눌러 결과지 서랍을 열고 선택지를 고르거나 직접 적어 "답 넣기"를 누르면 된다. 사용자가 채팅으로 답하면 세션이 `uv run jipsa answer <실행ID> "<답>" --close`로 기록해 확인 필요에서 빠지게 한다. 채팅으로 받은 답은 세션이 이미 받아 서브에이전트에 시키므로 `--close`를 붙여 받은편지함에 넣지 않는다(같은 일을 두 번 시키지 않는다). 스케줄러 작업자 실행을 그 답으로 이어 돌리게 할 때만 `--close` 없이 넣는다. 답 없이 확인만 하려면 결과지 아래 "답 없이 확인"을 누른다. 상태 값과 큐 보류는 그대로라 다시 돌지 않고, 답 칸은 확인 필요로 되돌리면 다시 열린다(261022-jipsa-51).

- 스케줄러 작업자의 실행이면 스케줄러가 다음 주기에 이어 돌린다.
- 이 세션이나 서브에이전트가 한 실행이면 답이 받은편지함에 적힌다. 세션이 쉬는 중이면 띄워 둔 답 대기 명령이 몇 초 안에 받음 표시를 하고 안내문을 찍고 끝나며, 그 끝남이 세션을 깨운다. 세션이 일하는 중이면 hook이 턴 끝이나 다음 입력 때 넘긴다. 어느 쪽이든 받음 표시가 남으므로 같은 답이 두 번 오지 않는다. "[jipsa] 대시보드 결과지에 답이 들어왔다" 안내가 오면 그 답대로 이어서 처리하되 일은 서브에이전트에 맡긴다(새 일이면 `jipsa begin`으로 시작해 `finish`로 끝낸다). 서브에이전트를 띄운 뒤 답 대기 명령을 다시 백그라운드로 띄운다. 답 대기 명령은 `--timeout 0`으로 띄워 시간 제한 없이 기다리게 한다. 띄운 세션이 사라지면 스스로 끝나므로 남지 않는다. 시간 제한을 주어 띄운 대기 명령(기본 12시간)이 답 없이 끝났을 때는 다시 띄운다.
- 완료나 실패로 끝난 실행도 선택지나 보고서 정할 것 번호 목록이 있으면 결과지 서랍에 답 넣기 칸이 열리고 `jipsa answer`도 받는다. 상태는 그대로이고 상태 값 확인 필요의 집계에 들지 않으며, 주체가 스케줄러 작업자여도 다시 돌리지 않고 같은 받은편지함으로 세션에 넘긴다. 서브에이전트의 result.json options에는 서로 대체하는 고를 안(1안, 2안, 가안처럼)만 상태와 무관하게 '1안: 내용' 꼴로 넣고, 서로 다른 결정과 할 일은 넣지 않는다. 비어 있으면 finish가 보고서 정할 것 번호 목록에서 안 이름으로 시작하는 항목만 골라 채운다. 서랍은 안마다 짧은 단추(1안, 2안)와 안 내용 글자를 두고, 나머지 정할 것은 단추 없이 글자로만 보인다. 단추를 누르면 답 칸에 안 이름이 채워지고 사용자가 '1안, 추가 지시'처럼 이어 쓴다. 안 이름으로 시작하는 답은 받은편지함 안내에 고른 안 내용이 같이 붙는다. 이름 없는 선택지는 상태가 확인 필요일 때만 1안, 2안 단추가 되고 끝난 실행에서는 글자로 보인다. 답 없이 결과지 아래 확인을 누른 끝난 실행은 답 칸이 사라지고 답도 받지 않는다(확인 필요로 되돌리면 다시 열린다). 답을 넣으면 그 실행은 자동으로 확인되어 확인 필요에서 빠지고, 답을 물리면 확인도 되돌린다(2026-10-22 사용자 승인, 261022-jipsa-45 나안과 다안, 261022-jipsa-48 추가 지시).
- 잘못 넣은 답은 `uv run jipsa answer <실행ID> --undo`로 물린다. 확인 필요였던 실행은 세션과 서브에이전트 실행만 확인 필요로 되돌리고, 끝난 실행에 넣은 답은 주체와 무관하게 답만 지우며 아직 세션에 넘어가지 않았으면 받은편지함에서도 뺀다.

## 모드 전환

- Auto 모드는 없어졌다(261029-jipsa-17). `jipsa auto`는 안내만 찍는다. Cycle은 `/todo run <번호> [시작 HH:MM] [마감 HH:MM|+4h]`로 시킬 때 시작과 마감을 정하고, 일회성 줄은 `/todo run <번호>`로 바로 돈다. 동시 실행 수, GPU와 RAM 나눔, 대기열은 모드와 무관하게 스케줄러가 맡는다. 마감이면 돌던 단계를 마치고 마감 결과지를 쓴 뒤 줄을 할 일로 돌리고, 다시 시키면 멈춘 자리부터 잇는다(판정까지 마친 회차면 다음 회차, 아니면 그 회차의 남은 단계).
- Cycle 목표는 할 일 줄의 cycle 칸(`cycle <지표> <목표값> 이상|이하 상한 N`)으로 적는다. 지표나 목표값을 비운 `cycle 미정`도 받고, Cycle 1 분석이 비운 칸을 정해 줄에 채운다. 차례가 오면 스케줄러 작업자가 명령 이행, 분석과 피드백, 목표 판정을 한 바퀴씩 돌고 끝 조건이나 마감까지 돈다. 그만두려면 `/todo stop <번호>`(대시보드 멈추기)를 쓴다. 판정은 수치 지표와 목표값이고 대리 지표는 쓰지 않는다.
- 사용 창(2026-11-02 사용자 답): Claude와 Codex 사용 창 비율로 새 시작, 시킨 줄, 세션 begin, Cycle을 막지 않는다. Cycle 새 단계는 합쳐 6개까지 같이 돈다. 실제 한도 오류가 나면 작업자는 총 상한까지 기다린 뒤 실패로 끝나고, Codex 한도면 Claude로 넘어간다. 사용 창 값은 표시만 한다(`jipsa status`의 사용 창 줄과 동시 실행 줄).
- Cycle 목표는 여러 개가 목표마다 따로 돌고, 한 목표 안의 단계는 차례로 돈다.
- GPU는 장부로 나눈다. 남은 자리는 전체에서 장부 몫 합, 장부 밖 실측(게임, 사람 작업), Cycle 단계 사이 10분 예약을 뺀 값이다. 모자라면 대기열에 서고, 순서는 사람이 정한 자리, 먼저 온 순서이며 맨 앞이 30분을 기다리기 전에는 빈 자리에 드는 작은 줄이 먼저 든다. 실측이 장부보다 크면 장부를 올리고 새 GPU 작업을 10분 멈춘다. 강제로 끄지 않는다. 대시보드 머리 줄 GPU 막대와 그 아래 대기열 띠에서 맨 앞으로, 내리기, 취소를 누른다.
- Cycle 목표가 끝나면 결과지 한 장이 남고 줄은 할 일 절로 돌아온다.

## Slack

확인 필요와 실패로 끝난 작업마다 한 줄이 간다. 스케줄러 작업자는 실행기가, 서브에이전트와 뒤늦은 기록은 `jipsa finish`와 `jipsa record`가 보낸다. Sol 공격이 있었던 실행은 보내는 한 줄 끝에 "(Sol 지적 N, 반영 M)"만 붙고 메시지 수는 늘지 않는다. 완료는 바로 보내지 않는다. 밤사이 끝난 Cycle은 아침 한 번(기본 07:30, JIPSA_MORNING_AT) 모아 한 글로 간다. 끄려면 `--no-slack`을 붙인다. 웹훅 값은 어디에도 출력하지 않는다.

## 하지 않는 것

- 스케줄러는 대시보드(`uv run jipsa web`)가 띄우고 꺼지면 다시 띄운다. 이 세션은 `uv run jipsa run`을 따로 켜지 않는다. 잠금이 있어 두 번째는 바로 끝난다(2026-10-22 사용자 승인). Remote Control 세션은 사용자가 손으로 켠다.
- 다음 할 일을 대신 정하지 않는다. 사용자가 말한 것만 넣는다.
- 서브에이전트를 `jipsa begin` 없이 띄우지 않는다.
- 푸시, 병합, 발행은 사용자가 그 행동을 직접 지시할 때만 이 세션의 권한으로 한다. jipsa 작업에 시키지 않는다.

## 토큰과 전용 규칙(2026-11-02 사용자 답, 261102-jipsa-50)

- 작은 일은 짧은 상한과 가벼운 모델로 띄운다.
- Sol 공격이 Codex 없음이나 호출 실패, 한도 오류로 돌지 않으면 공격 없음으로 마감하고 Claude가 대신 공격하지 않는다.
- 서브에이전트 Agent 호출에는 begin의 `--model` 값을 model 인자로 늘 명시한다.
- 10,000자를 넘을 파일과 출력은 크기를 먼저 보고 필요한 줄만 읽는다. 끝난 초안 HTML은 통째로 읽지 않는다.
- 긴 작업 지시는 begin 출력을 셸로 파일에 담아 경로만 넘긴다. 세션은 그 내용을 대화에 다시 쓰지 않는다.
- 보고서 옮겨 쓰기를 없애는 일은 보고서 넣기 코드가 들어간 뒤에 한다. 그때까지 위 3번 순서대로 세션이 옮겨 쓴다.
- 프로젝트 전용 규칙은 `docs/local/rules.md`에 있다. 파일이 있으면 begin 규격과 작업자 지시에 저절로 들어가므로 세션이 따로 옮기지 않는다. 고치는 일은 사람 지시로만 한다.
