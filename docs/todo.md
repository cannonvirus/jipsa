# 할 일 파일 형식

할 일은 상태 폴더의 `todo.md` 한 파일에 둔다. 폴더는 `JIPSA_STATE_DIR`로 바꿀 수 있다. 명령은 `uv run jipsa todo`, 세션에서는 `/todo` 스킬([claude-code.md](claude-code.md))이고 대시보드 TODO 탭도 같은 파일을 쓴다.

## 절

파일은 `## 할 일`, `## 메모` 두 절이다. 한 줄이 하나이고 `- `로 시작한다.

```
## 할 일
- my_app | 첫 화면 표시 시간 줄이기 | 첫 화면이 0.8초 안에 뜬다 | cycle 첫 화면 ms 800 이하 상한 4
- my_app | 설정 화면 입력 검증 추가 | 범위 밖 값을 넣으면 저장되지 않고 안내 문구가 보인다 | 한도 RAM 4GB, CPU 2

## 메모
- 의존성 목록 정리 생각해 보기
```

- 할 일 절은 넣어도 돌지 않는다. 한 줄을 돌리려면 `uv run jipsa todo run <번호>`다. Cycle 줄은 `uv run jipsa todo run <번호> [시작 HH:MM] [마감 HH:MM|+4h]`로 시작과 마감을 정한다.
- 메모 절은 프로젝트와 기준 규칙이 없는 자유 글이다. 큐가 읽지 않고, `uv run jipsa todo up m1 <프로젝트>`로 할 일 줄로 올린다.
- 번호는 할 일 절에서 1부터 매기고 메모는 m1, m2로 따로 매긴다.
- 옛 파일의 `## Auto` 절 줄은 할 일로 읽고, 파일을 고쳐 쓸 때 할 일 절로 합친다. Auto 모드는 없어졌다.

## 칸

`프로젝트 | 할 일 문장 | 기준 | cycle .. | 한도 ..`

- 첫 칸은 `projects/<이름>.toml`의 이름이고 둘째 칸은 할 일 문장이다. 둘 다 있어야 한다.
- 나머지 칸은 선택이다. 이름 없는 칸은 완료 기준이다. 기준을 비우면 차례가 올 때 기준 후보를 정하는 작업이 먼저 돈다.
- cycle 칸은 `cycle <지표> <목표값> 이상|이하`이고 끝에 `상한 N`(나아지지 않은 Cycle을 몇 번 연속까지 볼지), `도달하면 끝`을 붙일 수 있다. 지표와 목표값은 수치 지표나 기계가 판정하는 O/X여야 한다. 지표나 목표값을 `미정`으로 비우면 첫 분석이 정한다.
- 한도 칸은 `한도 VRAM 6GB, RAM 12GB, CPU 4`처럼 필요한 것만 적는다. 값은 0보다 커야 한다.
- 같은 프로젝트와 같은 문장의 줄은 하나만 둔다. 상태 표시는 적지 않는다.

## 동시 실행

Cycle의 새 단계와 기준 정하기는 합쳐 6개까지 같이 돈다(`/jipsa-config`의 자동 작업 동시 수). 사용 창 비율로는 막지 않는다. 실제 한도 오류가 나면 작업자는 총 상한까지 기다렸다가 실패로 끝난다. `todo run`으로 시킨 일회성 줄은 이 개수에 세지 않는다. GPU를 쓰는 줄은 GPU 할당 현황과 대기열을 거쳐 모자라면 기다린다.
